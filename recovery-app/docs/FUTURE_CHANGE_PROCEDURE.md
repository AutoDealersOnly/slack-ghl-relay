# Future Change Procedure for Restored ADO Functions

## Purpose

This procedure applies whenever ADO needs a future adjustment to the QR Pass Page Builder or any restored GoHighLevel–Slack automation. It is designed so that a future request can start from this thread, the private Recovery Index, and the company GitHub backup rather than from memory or an unrecoverable workspace.

## Start every requested change here

First, open the private recovery-vault Google document and locate the function’s **ACTIVE RECOVERY RECORD**. It identifies the purpose, existing GoHighLevel workflow or Slack command, published destination, GitHub repository, recovery branch, backup folder, specific source files, and test procedure. The private document holds exact private URLs and current protected-setting values; GitHub does not.

| Step | Required action |
|---|---|
| 1. Identify | Confirm the named function and its record in the private Recovery Index. Do not guess a workflow or create a duplicate one. |
| 2. Restore context | Connect GitHub and open `AutoDealersOnly/slack-ghl-relay`, branch `secure-recovery-relay-20260826`, folder `recovery-app`. |
| 3. Scope | Change only the requested behavior. Preserve existing triggers, workflow actions, payloads, recipients, and customer-facing formats unless the request specifically changes them. |
| 4. Protect credentials | Keep API keys, bot tokens, IDs, signing secrets, and private menu-link access values in protected settings and the private recovery document only. |
| 5. Test | Run focused tests and the complete suite. Use ABC Dealer for a live test whenever the change can affect GoHighLevel or Slack. |
| 6. Confirm | Obtain visual operational confirmation for Slack messages, Canvas behavior, or user-facing page changes. Do not treat a database log alone as final proof. |
| 7. Record | Update the function’s guide, Recovery Index, private ACTIVE RECOVERY RECORD, and test result. |
| 8. Back up | Save a project checkpoint and push the tested, secret-free source and documentation to the same recovery branch before beginning another function. |

## Rebuild after a loss

Connect GitHub, clone the company repository, and check out the recovery branch. Restore the `recovery-app` folder into a new project. Re-enter protected settings only from the private recovery document. Publish the replacement application, then change only the stale GoHighLevel Custom Webhook URL, Slack command URL, or GHL custom-menu link identified by the relevant Recovery Index entry. Test with ABC Dealer before approving an agency-wide action.

> **Standing recovery rule:** a function is not finished until its tested, secret-free source and rebuild instructions are pushed to the company GitHub recovery branch and its private Recovery Index record has been updated.
